# Validation Evidence — As Built

**Status:** implemented evidence index and checked results
**Code:** `transport/tests/`, `transport/benchmarks/`

This document maps current claims to executable evidence. It is not a roadmap.
Unimplemented work is tracked in [`FUTURE-ROADMAP.md`](FUTURE-ROADMAP.md).

## Evidence levels

| Level | Meaning |
| :-- | :-- |
| Unit | One component or invariant under controlled inputs |
| Integration | Multiple repository components exchange real interfaces |
| External comparison | A controller is compared with an independent implementation or RFC vector |
| Scenario | A versioned end-to-end configuration produces conserved, recorded results |

Passing a lower level does not imply a stronger one. In particular, controller
comparison does not establish equivalence to a complete Linux network stack.

## Checked result files

```text
transport/benchmarks/results/
  scale-objects.json
  scale-loss.json
  scale-prague.json
  sfv-pilot.json
  tcp-reference.json
  iperf-smoke.json
```

`scale-*.json` and `tcp-reference.json` are generated by their named runners.
`sfv-pilot.json` is a curated aggregate of the successful external integration
run; its source script and external revision are recorded in the file.
`iperf-smoke.json` is a curated summary of short TCP and UDP FikoreLink runs;
the emulator-backed automated tests are the authoritative behavioural gate.

Every checked result must identify:

- the runner or command;
- the tested FikoRE source revision;
- material external dependency revision, when applicable;
- simulated duration and scenario parameters;
- invariant results or metrics being cited.

Wall-clock durations are observations from one host. They support regression
tracking on comparable hosts but are not portable performance guarantees.

## Core invariants

Scenario evidence is accepted only when it checks the relevant conservation
identities.

For each segment:

```text
submitted bytes
  = delivered bytes
  + queue-dropped bytes
  + radio-dropped bytes
  + expired bytes
```

For each object after its cancellation tail is drained:

```text
transport-attributed bytes
  = useful/application-delivered bytes
  + cancelled-tail bytes
  + terminal network outcomes
  + transport bytes still pending
```

CE bytes are a subset of delivered bytes and must not be added as a fifth
terminal fate.

## External dependency evidence

The external TCP comparison uses a pinned ns.py v0.4.5 checkout and a pinned
Prague source file. The SFV validation uses the external v0.7.2 repository.
These tests are manually invoked because the dependencies are not vendored.

The checked JSON preserves the revision that was actually tested. Re-running
against another revision creates new evidence; it must not silently rewrite the
meaning of the old record.

## Claims deliberately not made

Current evidence does not prove:

- exact Linux TCP packet-for-packet behaviour;
- equivalence to real `iperf3`;
- all SFV harness scenarios or versions;
- performance on every host;
- correctness of features listed as unimplemented in the roadmap.

See [`09-external-tcp-validation.md`](09-external-tcp-validation.md) for the
controller comparison and [`LIMITATIONS.md`](LIMITATIONS.md) for current model
boundaries.
